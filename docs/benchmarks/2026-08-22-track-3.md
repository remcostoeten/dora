## What changed in the product

- Rust: `QueryEvent { columns, row_batch, progress, done, error }` pushed
  through `tauri::ipc::Channel` by `StatementManager` for `start_query_stream`;
  the polling `start_query`/`fetch_query` path is kept behind
  `VITE_QUERY_STREAMING=0`. Result pages are 500 rows (were 50) for SQLite,
  Postgres and DuckDB. Cancellation emits `error` on the channel.
- Frontend: `executeQuery` returns `rows` (first page) plus a `rowSource` whose
  `rows(range)` is backed by buffered pages and on-demand `fetch_page`, and
  `pages()` for explicit full reads. `onRows` delivers the first page as a
  preview before the query finishes. SQL results virtualize over `rowCount` and
  load windows on scroll. Export, copy-JSON, the Drizzle/Prisma runners and the
  HogQL hook materialize through `collectQueryRows`; nothing else reads every
  page.
- Harness: the first-paint scenario submits SQL through the capture hook,
  iterates, and waits for the app to go quiet before the next scenario — the
  mock's delayed final result and async row count otherwise leak into the
  keystroke window (one intermediate run showed 6 phantom keystroke commits for
  exactly that reason).

## Reading these numbers

**First paint is bounded by one page, not the result.** 100k rows paint in
under 90 ms because the table renders the first 500-row page as soon as it
arrives and never waits for the rest. The mock adapter's own delay
(100–300 ms) is deliberately placed *after* the preview, so the number describes
the renderer path from submit to first cell.

**Navigation timings did not move, and were not expected to.** Those scenarios
are dominated by one long synchronous frame (worst 311 ms) on the Data Viewer
path. Note the fixture is 2,000 columns *across* 200 tables (4–40 per table),
so column count alone does not explain it; the frame has not been profiled yet.
Candidates: the un-virtualized 200-table sidebar list re-rendering on
selection, the Data Viewer mount path, and derivations over the table snapshot.
The streaming transport changes what arrives, not how that path renders. That
frame is the next target.

## Next

  `cached-table-switch`), then fix what it points at: virtualize the sidebar
  table list, column-virtualize/memoize the grid, or memoize a snapshot
  derivation. This is what the four navigation budgets are waiting on.
- Row encoding: rows already travel as arrays with columns sent once; a
  binary/columnar encoding for very large pages is still open and should be
  decided from a measurement against the real Tauri adapter, not the mock.
- Drizzle/Prisma results panels still materialize the full result; moving them
