# Benchmark — 2026-08-22, after Tracks 1 and 2

Second run of the harness, with keep-alive views and the persistent editor host
(Track 1) and the normalized workspace store (Track 2) landed. Compare against
`2026-08-22-baseline.md`, which is the same machine and the same fixtures before
either track.

**Every render invariant is now green. No timing budget is met yet.** Both
halves of that sentence matter: the structural claims the contract makes are
enforced, and the remaining gap is a single long synchronous frame per
navigation that Track 3 targets.

## Reading these numbers

**The keystroke invariant is the headline.** 114 commits per 58 characters is
now 0. Monaco's content no longer travels up through the shell: the SQL console
publishes its editor context to a store the assistant panel subscribes to, so a
keystroke commits a leaf, or nothing at all, instead of the whole workspace.

**"Zero IPC" is now counted, not inferred.** The mock adapter wraps itself in a
call counter, and the invariant asserts that switching to an already-visited
table paints without a single `fetchTableData`. That is the snapshot store
working: navigation reads the last known rows synchronously and reconciles in
the background.

**The timings did not follow the commits down.** Five commits and zero fetches
still cost 400 ms, so the remaining cost is neither React bookkeeping nor the
adapter — it is one long synchronous frame (worst 382 ms) spent rendering the
grid. The fixtures are deliberately hostile here: 2,000 columns across 200
tables. Track 3 (windowed grid, streaming transport) is the track that owns
this, and no amount of store work moves it.

**Connection switch improved most in absolute terms** (−301 ms), which is what
dropping the per-connection remount plus a cached schema buys.

## A harness fix in this run

`measureConnectionSwitch` now waits for the connection menu to finish its 200 ms
exit animation before re-opening it. Radix keeps the dismiss layer mounted for
the length of that animation, so re-opening inside the window makes the layer
treat the trigger press as an outside interaction and dismiss the menu it just
opened. The baseline run never hit this because a connection switch took long
enough for the animation to finish first; at 450 ms it does not. No measured
span covers the wait.
