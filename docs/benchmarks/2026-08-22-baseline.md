# Performance baseline — 2026-08-22

First run of the Track 0 harness, against `master` before any of the
architecture work. Every number here is the *starting* state: what Studio costs
today, so later tracks have something to be measured against.

Budgets are defined in `docs/performance-contract.md`. Nothing here meets one.
That is the expected result, not a surprise — the roadmap's premise is that
views are branches of a ternary in `pages/Index.tsx` and table navigation has no
snapshot store, and these numbers are what that costs.

| Invariant | Result |
| --- | --- |

## Reading these numbers

**The keystroke result is the sharpest.** Two React commits per character means
the shell re-renders twice for every key pressed in Monaco. It is also the one
number no hardware difference can explain away, which is why it is an invariant
rather than a timing.

**Roughly 100 ms of each switch is the mock adapter, not the renderer.** The
mock adapter sleeps 50–150 ms per fetch on purpose (`randomDelay`). Anything
that reaches it inherits that floor, so the table- and connection-switch numbers
are upper bounds on renderer cost. The gap between the ~100 ms floor and the
observed 300–800 ms is the part the architecture owns — and the fact that a
*cached* switch pays the adapter at all is itself the finding.

**View switches never touch the adapter and still cost 390–735 ms.** That is
teardown and rebuild: 12–13 commits, a fresh grid or a fresh Monaco each time.
No amount of query tuning affects it.

**The 100k-row first paint at 360 ms is the least bad result.** The grid already
virtualizes rows; the cost is in getting to the first frame rather than in the
row count.

## What this baseline does not yet cover

- **Cold start (budget 6) is unmeasured**, so the contract leaves it unset.
  With the perf fixtures the mock store deep-copies 100k rows on every load
  (~120 ms) and its `localStorage` write exceeds quota and silently fails, so a
  number taken now would describe fixture seeding rather than app boot.
- **"Zero IPC" is inferred rather than counted** — the adapter's artificial
  delay stands in for a call counter until Track 2 introduces a seam. See the
  harness README.
- **60 fps scroll on the 100k table is not yet driven.** Long frames are
  recorded run-wide, but no sustained-scroll scenario exists.
